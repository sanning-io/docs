This page puts one anchor call inside an agent you already have. What comes
back is a signed commitment to that step, which a third party can check later
without Sanning and without you.

Before you start, finish the [Quickstart](/quickstart) steps that create a Sandbox API
key, make a signing seed and install the SDK. This page does not repeat them. It covers
the call itself and what to know before you wire it into a service.

## Anchor one event

Build the anchorer once, when your service starts, and call `anchor` at the
point where the agent does something you want on the record. A plain `anchor`
call builds an `event` record. For a record that has an agent type, such as a
decision, see [Record a decision](#record-a-decision).

<CodeGroup>

```ts TypeScript
import {
  createAnchorer,
  FsLogStore,
  LocalEd25519Signer,
} from "@sanning/anchor";

// Read the environment once and fail fast. `process.env.X` is
// `string | undefined`, so an assertion here would assert exactly what
// this check exists to disprove.
const apiKey = process.env.SANNING_API_KEY;
const seedHex = process.env.SANNING_SIGNING_SEED;
if (!apiKey || !seedHex) {
  throw new Error("set SANNING_API_KEY and SANNING_SIGNING_SEED");
}

const anchorer = createAnchorer({
  // Your agent's identity. The seed stays on your machine.
  signer: LocalEd25519Signer.fromSeedHex(seedHex),
  subject: { type: "agent", agent_id: "claims-triage" },
  apiKey,
  // Keeps the bytes the commitment is over. See the log store guide.
  logStore: new FsLogStore("./logstore"),
});

const step = { claim: "CLM-4417", action: "referred" };

const result = await anchorer.anchor({
  // Hashed in this process. These bytes are never sent to Sanning.
  content: JSON.stringify(step),
});

console.log(result.eventId);

// Settles every event. Throws if anything was signed and never delivered.
await anchorer.close();
```

```python Python
import json
import os

from sanning_anchor import Anchorer, FsLogStore, LocalEd25519Signer

anchorer = Anchorer(
    # Your agent's identity. The seed stays on your machine.
    signer=LocalEd25519Signer.from_seed_hex(os.environ["SANNING_SIGNING_SEED"]),
    subject={"type": "agent", "agent_id": "claims-triage"},
    api_key=os.environ["SANNING_API_KEY"],
    # Keeps the bytes the commitment is over. See the log store guide.
    log_store=FsLogStore("./logstore"),
)

step = {"claim": "CLM-4417", "action": "referred"}

result = anchorer.anchor(
    # Hashed in this process. These bytes are never sent to Sanning.
    content=json.dumps(step).encode(),
)

print(result.event_id)

# Settles every event. Raises if anything was signed and never delivered.
anchorer.close()
```

</CodeGroup>

Replace the following:

- `SANNING_SIGNING_SEED` with 64 lowercase hex characters that your service
  keeps across restarts.
- `SANNING_API_KEY` with the Sandbox API key from the console.
- `claims-triage` with the name you want this evidence attributed to.

Neither sample sets an environment. The Sandbox API key decides it, and the SDK signs
the matching value. A Live API key writes to a permanent public record, so moving to Live
is a deliberate edit of your secrets, not of this code: [Go live](/guides/go-live)
covers the move.

## Enrollment is automatic

Neither SDK needs a registration step, and its absence is not an omission. On
the first `anchor` call, the SDK proves possession of your signing key to the
control plane, and the agent appears on the console's **Agents** page under its
own key. One organization API key covers all of your agents.

Do not write an enrollment call. If you would rather enroll at deploy time,
[API keys and scopes](/guides/keys-and-scopes) shows how to turn the automatic
call off and drive it yourself.

## What leaves your process

The content you pass to `anchor` is hashed where you pass it. Only the signed
envelope travels, and it carries a salted hash of the record, never the content.
Sanning is content-blind in Private mode by construction rather than by policy: it never receives the
bytes, so it cannot disclose them. The full boundary is on the
[Introduction](/).

Two consequences reach your code:

- **`eventBytes` in TypeScript, `event_bytes` in Python, are yours to
  keep.** They are what `payload_hash` commits to, and Sanning never holds
  them. Configuring a log store, as both samples do, discharges that for you.
- **A locator binds as your own assertion.** Anything you pass as `ref` or
  `payloadRef` is signed verbatim and published permanently. Keep a bucket
  path, a tenant id and a person's name out of both.

## The signing seed is the agent's identity

An agent is its key, not its name. Generate a 32-byte seed once, keep it in
the secret store you already run, and load the same seed on every boot:

```bash
openssl rand -hex 32
```

A fresh key each run is read as a rotation of an identity that is already
producing evidence, so it works on the first boot and fails on the second with
`RotationUnauthorizedError`.

<Warning>
  The two languages disagree on hex case. TypeScript's `fromSeedHex` accepts
  64 lowercase hex characters and throws `Ed25519 seed must be 64 lowercase
  hex chars` on anything else. Python's `from_seed_hex` accepts uppercase.
  The same seed, stored uppercase, works in Python and fails in TypeScript.
  Write seeds in lowercase and both languages read them.
</Warning>

## Event types are a closed set

A record has one of the 18 `agent.*` types on [Event types](/reference/event-types), or
one of seven types outside that vocabulary. Plain `anchor()` builds `event`,
`checkpoint` or `declaration`, and builds `event` when you name no type.

The SDK refuses to sign the following, at the call and before anything is sent:

- An `agent.*` type passed to plain `anchor()`, such as `agent.decision`. The SDK
  raises `InvalidRecordError` with the reason `event_schema_missing`. An `agent.*` record
  comes from an adapter or from the agent record builder.
- A type outside the set, such as `claims.decision`. The SDK raises
  `InvalidRecordError` with the reason `event_type_not_in_set`. A verifier reads a
  record of that type as `nonconforming`.

For a record that describes what the agent did, such as a model call or a tool call,
use an adapter, which writes the right type for each moment. See
[What to record](/guides/what-to-record).

## Record a decision

Use `agent.decision` when the agent states a business outcome. Build the record with
the agent record builder and pass it to `anchor` as `buildRecord` (`build_record` in
Python). The builder checks the record against the `sanning.agent/1` schema. If the
record breaks the schema, the SDK raises `InvalidRecordError` and signs nothing.

Name the decision for what is decided, and put the result in the value. Use the name
`credit_verdict` with the value `declined`. Do not use the name `credit_declined`:
a name that holds one result stops a reader comparing decisions.

<CodeGroup>

```ts TypeScript
import { randomUUID } from "node:crypto";
import {
  agentContent,
  buildAgentRecord,
  createAnchorer,
  decisionContent,
  FsLogStore,
  LocalEd25519Signer,
} from "@sanning/anchor";

const apiKey = process.env.SANNING_API_KEY;
const seedHex = process.env.SANNING_SIGNING_SEED;
if (!apiKey || !seedHex) {
  throw new Error("set SANNING_API_KEY and SANNING_SIGNING_SEED");
}

const anchorer = createAnchorer({
  signer: LocalEd25519Signer.fromSeedHex(seedHex),
  subject: { type: "agent", agent_id: "claims-triage" },
  apiKey,
  logStore: new FsLogStore("./logstore"),
});

const content = agentContent(
  decisionContent({ name: "claim_route", value: "referred" }),
);

// A decision outside any run is a run of one record.
const runId = randomUUID();

const result = await anchorer.anchor({
  // Hashed in this process. These bytes are never sent to Sanning.
  content: content.bytes,
  buildRecord: ({ subject, chainKey, previousHash }) =>
    buildAgentRecord({
      type: "agent.decision",
      subject,
      ...(chainKey !== undefined ? { chainKey, previousHash } : {}),
      content,
      metadata: {
        run: {
          run_id: runId,
          parent_run_id: null,
          root_run_id: runId,
          seq: 0,
          prev_event_id: null,
        },
        otel: {
          scope: {
            name: "@acme/claims-triage",
            version: "1.0.0",
            schema_url: "https://opentelemetry.io/schemas/1.41.0",
          },
        },
        decision: { name: "claim_route" },
      },
    }),
});

console.log(result.eventId);
await anchorer.close();
```

```python Python
import os
import uuid

from sanning_anchor import (
    Anchorer,
    FsLogStore,
    LocalEd25519Signer,
    agent_content,
    build_agent_record,
    decision_content,
)

anchorer = Anchorer(
    signer=LocalEd25519Signer.from_seed_hex(os.environ["SANNING_SIGNING_SEED"]),
    subject={"type": "agent", "agent_id": "claims-triage"},
    api_key=os.environ["SANNING_API_KEY"],
    log_store=FsLogStore("./logstore"),
)

content = agent_content(decision_content(name="claim_route", value="referred"))

# A decision outside any run is a run of one record.
run_id = str(uuid.uuid4())


def build(subject, chain_key, previous_hash):
    return build_agent_record(
        event_type="agent.decision",
        subject=subject,
        chain_key=chain_key,
        previous_hash=previous_hash,
        content=content,
        metadata={
            "run": {
                "run_id": run_id,
                "parent_run_id": None,
                "root_run_id": run_id,
                "seq": 0,
                "prev_event_id": None,
            },
            "otel": {
                "scope": {
                    "name": "acme-claims-triage",
                    "version": "1.0.0",
                    "schema_url": "https://opentelemetry.io/schemas/1.41.0",
                },
            },
            "decision": {"name": "claim_route"},
        },
    )


result = anchorer.anchor(
    # Hashed in this process. These bytes are never sent to Sanning.
    content=content.bytes,
    build_record=build,
)

print(result.event_id)
anchorer.close()
```

</CodeGroup>

Replace `@acme/claims-triage` (`acme-claims-triage` in Python) with the name and
version of your own package. `otel.scope` names the code that wrote the record. The
`content.bytes` are the canonical bytes that `event.content_hash` commits to. Keep
them: a verifier hashes them.

## Every record carries a random salt

The SDK writes a fresh random salt, `context.salt`, into every record it builds. The
salt stops anyone who holds only the envelope from confirming a guessed short value
against `payload_hash`. Without it, someone could rebuild the record from a guess, hash
it, and compare the result.

Sanning does not receive the salt. No builder option sets it. A record you build
yourself and pass in through `buildRecord` is signed with the salt it carries.

## See which records the SDK refused

A refused record is a hole a verifier would see, so the SDK reports it as well as
raising. `recordingStatus().refused` (`recording_status().refused` in Python) lists
each refused record, oldest first. Each entry has the event id, the type, the reason and
the JSON Pointer to the field at fault. An entry never holds a value from the record.

<CodeGroup>

```ts TypeScript
for (const refused of anchorer.recordingStatus().refused) {
  console.log(refused.eventId, refused.eventType, refused.reason, refused.at);
}
```

```python Python
for refused in anchorer.recording_status().refused:
    print(refused.event_id, refused.event_type, refused.reason, refused.at)
```

</CodeGroup>

For an `agent.decision` passed to plain `anchor()`, the entry reads
`agent.decision`, `event_schema_missing`, `/extras/event_schema`.

## Close the anchorer before the process exits

`close` settles every event and reports the ones that were signed and never
delivered. It throws or raises when any remain, because a timeout says nothing
about whether the control plane accepted the envelope.

<CodeGroup>

```ts TypeScript
anchorer.gaps; // each carries the eventBytes for one event
await anchorer.close(); // throws IncompleteTrailError if any remain
```

```python Python
anchorer.gaps          # each carries the event_bytes for one event
anchorer.close()       # raises IncompleteTrailError if any remain
```

</CodeGroup>

`anchorer.gaps` covers every record on the anchorer. A LangChain handler or a
Vercel middleware reports and raises only on the
records it handed over, and none of them closes the anchorer, so you call
`close` here yourself.

Retain the `eventBytes` on every gap before anything else. After a failed
delivery they are the only copy of something the control plane may already
hold.
