Two commands, owned by two packages, and the split matters.

| Command | Package | Who runs it |
|---|---|---|
| `bundle` | `@sanning/anchor`, `sanning-anchor` | You, to hand evidence over |
| `verify` | `@sanning/proof`, `sanning-proof` | Whoever you hand it to |

**An auditor never needs the write SDK.** Verification lives in its own package with no
account and no key, and no network unless you choose to pass a gateway URL for the
optional online check (see below).

## bundle

Assemble the hand-over pack for one agent over one period. This section is linked as
`docs.sanning.io/reference/cli#bundle` from the console's **Evidence** page.

<CodeGroup>
```bash TypeScript
npx @sanning/anchor bundle \
  --agent claims-triage \
  --from 2026-09-01 \
  --to 2026-09-30 \
  --logs ./logstore \
  --out pack.zip
```

```bash Python
sanning-anchor bundle \
  --agent claims-triage \
  --from 2026-09-01 \
  --to 2026-09-30 \
  --logs ./logstore \
  --out pack.zip
```
</CodeGroup>

Same flags, same exit codes, same output in both languages. One shared fixture grades
them, and neither passes by agreeing with the other.

| Flag | Required | Meaning |
|---|---|---|
| `--agent` | Yes | The agent whose records to gather. Use the name you anchored under |
| `--from` | Yes | Start of the period |
| `--to` | Yes | End of the period. A date-only bound names a whole day and is included; an ISO instant is exclusive |
| `--logs` | In practice | Your store root: the local directory holding `content/` and `records/`, or `s3://bucket` or `s3://bucket/prefix` |
| `--out` | Yes | Where to write the zip |
| `--allow-unstamped` | No | Assemble even when records in the period are not yet stamped. Takes no value |
| `--case` | No | From 0.15.0. Select the records whose own `context.case_id` is this case, and declare the pack about it. See [Hand over and verify a case](/guides/handoff-case#bundle-one-pack-per-agent) |

<Note>
  `--logs` is optional to the parser and required in practice. The command reads your
  record objects to work out which events are this agent's, because a
  minimum-disclosure envelope does not carry that name.
</Note>

**Authentication** comes from `SANNING_API_KEY` in the environment. There is no flag for
it. The key needs `anchor:read`.

**A declaration needs `SANNING_SIGNING_SEED`.** Set it to the seed of the agent whose
records you are bundling, 64 lowercase hex characters, and `bundle` signs a declaration,
the pack's own statement of what it holds, and seals the pack with that key. Without it,
`bundle` seals the pack with a one-time key it mints and discards, and builds no
declaration. With it set, `bundle` refuses a window holding a record that names no case,
a window holding more than one case, and an `s3://` log store. See
[Hand over and verify a case](/guides/handoff-case#bundle-one-pack-per-agent).

**`--agent` is checked twice.** The records route the command reads from filters by this
name on the server, and the command also refuses if a record it gets back names a
different agent. A misspelled `--agent` surfaces as a 404 from the records route rather
than an empty or mismatched pack.

**It verifies its own output before writing.** If the assembled pack does not verify,
nothing is written and the command exits non-zero. A pack that only fails at the auditor
is a pack shipped broken.

## Pack reporting

After `bundle` writes the pack, it reports that it did so to Sanning, using the same API
key, so the pack appears under **Evidence** in the console. The report carries your
agent's name, the environment, the window, the record count, the SHA-256 of `bundle.json`,
the SDK name and version, and the time the pack was built. It never carries the pack, a
log, a record id, or a file name, and Sanning never receives the pack itself.

Every run of `bundle` builds a new `bundle.json` with its own build time, so every run is
reported, even one covering a period you have already handed over.

If the report fails, `bundle` prints one line naming the pack's digest and still exits 0:
the pack was assembled and verified before the report was attempted, so a reporting
failure does not undo it. The credential needs `anchor:read`, the scope it already holds
to read your records back.

## verify

Check a pack. No account, no key, no relationship with Sanning.

```bash
npx @sanning/proof verify bundle.json --logs logs/
```

| Argument | Meaning |
|---|---|
| `bundle.json` | The bundle file, extracted from the pack |
| `--logs` | The folder of disclosed files, if the pack carries them |
| A gateway URL | Optional positional. Re-fetches the witness and byte-compares it |

| Exit | Means |
|---|---|
| 0 | Verified |
| 1 | A check ran and failed, or the pack deviates from its own declaration. The output names the record |
| 2 | The input could not be read |
| 3 | Undetermined: the pack reads `incomplete`, or a gateway re-fetch was asked for and something in it could not be checked |

Only an `arweave` witness with a 43-character transaction id is re-fetched from a
gateway. A witness of any other kind, or an id that is not exactly 43 characters, is
reported as not checked, and the run answers `partial` and exits `3`.

`sanning-proof` on PyPI is the same kernel and ships the same `verify` command. See
[Verify at the command line](/verify/cli).

## case

From `@sanning/proof` and `sanning-proof` 0.12.0. Read several packs as one case and
print one verdict, with every exception named. Name each pack as an unzipped directory or
as its zip.

```bash
npx @sanning/proof case assessor-pack/ reviewer-pack/
```

| Exit | Case verdict |
|---|---|
| 0 | `verified` |
| 1 | `failed` |
| 2 | `malformed`, or an input that cannot be read as a case |
| 3 | `incomplete` or `partial` |
| 4 | `mixed` |

`--gateways` takes a comma-separated list and re-fetches each witness, outside the case
reading. See [Hand over and verify a case](/guides/handoff-case#verify-at-the-command-line).

## Getting help

`--help` works on the top-level command in both languages. On a subcommand it exits 2 with
`unknown argument: --help`, which is a rough edge rather than a failure.

```bash
sanning-anchor --help
npx @sanning/anchor --help
```
